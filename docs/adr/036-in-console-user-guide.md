# ADR-036: In-Console User Guide

**Date:** 2026-10-01
**Status:** Accepted
**Relates to:** ADR-034 (Forge Console web UI), ADR-023 (forge-launcher npm package)

---

## Context

The Forge Console ships a Help dialog (`dashboard/views/help.ts`) with static
inline content — "What is this?", the pipeline, the views, and key terms. The
full walkthrough lives separately in the repo's `docs/forge-console-user-guide.md`.
A user in the browser had to leave the console and open the repo docs to follow
the end-to-end flow, and the inline help duplicated (and could drift from) the
longer guide.

We wanted the complete walkthrough reachable from within the UI, while keeping
the concise quick reference for users who just need a lookup. The guide must be
shipped with the published `forge-launcher` package (which does not contain the
repo's `docs/` directory), and must render with the console's existing
dependency-free markdown renderer.

## Decision

- **A tabbed Help dialog.** The Help modal gains a **User guide** tab alongside
  the existing **Quick help** content, so both a fast reference and the full
  walkthrough live in one surface. No new top-nav item — the dialog is already
  the help affordance and the nav stays uncrowded.
- **The guide ships as a client asset.** The build step
  (`copy-client-assets.mjs`) copies `docs/forge-console-user-guide.md` from the
  repo into the compiled client as `resources/console/client/guide.md`,
  mirroring how `stage-resources.mjs` already stages `prompt-playbook.md`. The
  console server serves it statically at `/guide.md` (the `.md` extension was
  added to the MIME map), confined by the existing `readStatic` traversal guard.
- **Rendered with `renderMarkdown`.** The client fetches `/guide.md` as text
  (`api.guideMarkdown()`) and renders it with the existing markdown renderer,
  cached after first load so tab switches do not refetch.
- **Local doc links are non-navigable.** Relative links in the guide (e.g.
  `forge-console.md`) cannot resolve inside the served page and would open a
  404 in a new tab. Rendering strips the `href` for any link without an
  `http(s)`/mailto scheme or a `#` fragment, leaving the text visible;
  external links remain clickable.
- **Guide content is maintained in the repo.** The source of truth stays
  `docs/forge-console-user-guide.md` (also linked from the README); the client
  copy is a build artifact regenerated on `npm run build`.

## Consequences

- The full walkthrough is one click away from any console view, and the quick
  reference remains for fast lookups.
- There are now two copies of the guide on disk (repo `docs/` and the built
  client); they stay in sync because the client copy is generated by the build,
  not hand-edited. Contributors must run `npm run build` (or `prepack`) before
  the console reflects guide edits.
- The static `guide.md` is served from the client directory, so the injected
  `clientDir` in console tests doubles as the fixture location for the new
  `/guide.md` test.
- Relative in-guide links render as plain text; if a future guide needs
  navigable internal links, a small resolver (e.g. an endpoint serving repo
  docs) would be added.
