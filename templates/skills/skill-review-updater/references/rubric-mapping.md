# Rubric Mapping

> Load when: Comparing new evidence to existing skill-review checks in Step 3.

Use this table format to prevent silent mismatch between "new" proposals and existing rubric coverage.

| Proposed rule | Source citation | Target axis | Existing check match | Gap type | Proposed addition |
|---|---|---|---|---|---|
| {short rule label} | {url or citation id} | {one of six axes} | {exact existing check label or "none"} | {missing \| weak \| outdated} | {new check text} |

## Normalization rules

1. Normalize each rule to one sentence with one enforceable behavior.
2. Merge near-duplicates before scoring impact.
3. If an existing check is semantically equivalent, classify as "covered" and do not propose as new.
4. If a rule spans multiple axes, pick a primary axis and note secondary impact in comments.

## Gap-type guidance

- **Missing:** No equivalent check exists.
- **Weak:** Check exists but is vague or non-enforceable.
- **Outdated:** Check conflicts with newer best-practice guidance or omits new constraints.
