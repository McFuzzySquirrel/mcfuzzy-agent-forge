# Define the guided project lifecycle

Type: grilling
Status: resolved

## Question

What are the exact plain-language steps, user decisions, and completion criteria in the beginner path from an initial idea to a reviewed plan and a running build?

## Answer

1. A user can start with just an idea. The Console creates a resumable project workspace immediately, saves progress continuously, and suggests an editable name.
2. Idea exploration and Project-brief authoring are two clearly marked phases of one continuous interactive experience. Neither is headless or skippable. Supplied notes or an existing PRD provide context but do not bypass interactive authoring. Users can leave nonessential details unknown, with assumptions and open questions surfaced.
3. The **Project brief** is the user-facing outcome-and-scope artifact: intended outcome and audience, capabilities, in/out of scope, success criteria, assumptions, and open questions. The user can revise it before approval. “PRD” remains an advanced/documentation term.
4. Approving the brief authorizes project preparation (team, skills, and build plan) only. Preparation runs as one guided background step with plain-language progress; it does not start execution.
5. When preparation is ready, the Console shows a concise explanation of what the build will do, its major phases, assumptions, and anything needing attention. Agent/task details remain optional under Developer tools. The user explicitly selects **Start build** to begin execution.
6. This flow reaches its success point when the user can see that the build is running. Further live monitoring and board details are covered by the other map decisions.
