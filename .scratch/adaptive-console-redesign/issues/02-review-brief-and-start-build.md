# 02: Review a Project brief before starting a Build

**What to build:** A Project author can review and edit the Project brief,
request changes or approve it, follow preparation, and explicitly start the
Build only after the prepared plan is ready.

**Blocked by:** 01: Guide a new Project through Idea authoring.

**Status:** ready-for-agent

- [ ] The review checkpoint presents an editable Project brief and a persistent
  at-a-glance summary in normal page flow.
- [ ] **Request changes** returns the user to interactive authoring; **Approve**
  is a separate, explicit action.
- [ ] Approving the Project brief authorizes preparation only and never starts
  Build execution.
- [ ] Preparation appears as one guided background step with plain-language
  progress and actionable failure information.
- [ ] When preparation is ready, the user sees a concise summary of the Build,
  its major phases, assumptions, and anything needing attention.
- [ ] Build execution starts only after the user selects **Start build**.
- [ ] Project brief approval remains distinct from approval of a runtime Human
  review Task.
- [ ] Affected Console documentation and visual captures reflect the delivered
  flow.
