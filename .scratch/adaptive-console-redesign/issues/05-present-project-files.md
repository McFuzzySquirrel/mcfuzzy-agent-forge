# 05: Present useful deliverables as Project files

**What to build:** A user can find and open the important documents and
deliverables for a Project without needing to understand per-Task artifact
provenance.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] The Project files destination foregrounds useful Project documents and
  deliverables in language that makes their purpose clear.
- [x] Opening a Project file provides a useful view or a clear supported
  external-open action.
- [x] Detailed per-Task artifact provenance remains available in Artifacts and
  is not confused with the Basic Project files collection.
- [x] Missing or unavailable files produce an explanatory state rather than a
  broken or empty-looking view.
- [x] Viewing or opening Project files does not alter or remove repository
  content.
- [x] Affected Console documentation and visual captures reflect the delivered
  view.
